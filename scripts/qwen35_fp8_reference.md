# Qwen3.5-35B-A3B numeric-FP8 external reference

This script is independent of `scripts/qwen35_reference.py`, the existing
0.8B F32 oracle. It does not import Ferrule production code, modify a model
family forward, run vLLM, install dependencies, use NCCL, or initialize CUDA.

## Run

Use the existing environment, not PATH Python:

```sh
/opt/conda310/bin/python -B scripts/test_qwen35_fp8_reference.py
/opt/conda310/bin/python -B scripts/qwen35_fp8_reference.py --tiny-only
/opt/conda310/bin/python -B scripts/qwen35_fp8_reference.py --timeout 900 --capital --cache-states
/opt/conda310/bin/python -B scripts/qwen35_fp8_reference.py --precision f32 --timeout 900 --capital --cache-states --output target/validation/qwen35-fp8-reference-full40-f32-v1
```

Default checkpoint: `/mnt/nas1/hf/Qwen3.5-35B-A3B-FP8`. The full run requires
its native 40-layer / 256-expert text config. Vision and MTP are excluded.
`--capital` adds the capital prompt; Hello always runs. Each case is independent,
batch 1, plain tokenization without a chat template or special tokens.

Only fresh `target/validation/qwen35-fp8-reference-*` directories are accepted.
A tiny-only run needs no NAS payloads. Both modes first run the precision golden
and native two-layer miniMoE/GDN/full-attention golden. `--output` can name a
fresh directory within the same allowed prefix; existing directories are refused.

## Explicit precision profiles

`--precision bf16_rne` is the unchanged default; `--precision f32` is opt-in.
They are different validation contracts, not two reduction-order approximations
of one contract. Loader caches and expert/linear adapters reject mixed profiles.

| Profile | FP8 dequantized weight | Quantized Linear input | Accumulation/output | Schema |
| --- | --- | --- | --- | --- |
| `bf16_rne` (default) | F32 multiply then BF16-RNE, represented in F32 | BF16-RNE represented in F32 | F32 | `ferrule.qwen35-fp8-reference.v1` |
| `f32` | F32 multiply, **no BF16 rounding** | F32 unchanged | F32 | `ferrule.qwen35-fp8-reference.f32.v1` |

For `f32`, the precise weight is `F32(E4M3FN) * F32(BF16_numeric_scale)`;
activations remain F32. CPU `torch.nn.functional.linear` uses strict F32
operands, accumulation and output, with TF32 disabled. The BF16 scale storage is
NOT changed to E8M0 or reciprocals. Native TF layers/GDN/router/shared expert
remain F32. No Ferrule kernel is called and CUTLASS reduction order is not
emulated. Nonquant checkpoint BF16/F32 weights become/stay F32 in both profiles.

### Legacy BF16-RNE profile — not an all-BF16 Transformers run

For every quantized matrix with `--precision bf16_rne`:

1. Decode safetensors `F8_E4M3` as PyTorch `float8_e4m3fn` (finite E4M3).
2. Multiply in F32 by the **numeric BF16**
   `weight_scale_inv[row // 128, column // 128]`.
   Despite its name this is **not a reciprocal, exponent, or UE8M0 scale**.
3. Round the dequantized weight to BF16, round-to-nearest-even, then represent
   that rounded value in F32.
4. Round this linear call's activation to BF16-RNE and convert it to F32.
5. Call F32 `torch.nn.functional.linear`: F32 accumulation **and F32 output**.
   There is no BF16 output rounding, and no extra BF16 residual/model boundary.

Nonquantized BF16 checkpoint weights are converted directly to F32. Source F32
parameters (including GDN `A_log` and gated norm weights) stay F32. Nonquantized
projections, embeddings, convolution, router, norms, residuals and other native
TF operations compute in F32. This is the CPU F32 reference option, **not a
claim of bitwise equivalence to a CUDA TF32x3 implementation**. TF32 is explicitly
disabled for both CUDA matmul and cuDNN; matmul precision is `highest`.

All attention, GDN chunk/recurrent rules, normalization, router top-k,
shared-expert sigmoid gate and expert combination formulas come from the locally
installed **Transformers 5.2.0 `qwen3_5_moe` modules**. The script rejects FLA /
causal-conv accelerated paths. The native source file and its SHA256 are recorded.

### Auditable adapters

- `LazyLinear` supplies weights and the input precision boundary to a linear
  call. Biases are absent in this text checkpoint; unexpected biases fail.
- `ExpertBank` replaces only the native experts' two weight attributes. Indexing
  a gate/up bank loads the selected split checkpoint expert and concatenates
  gate then up along rows, as the TF class expects.
- `ProductWeight` is a Tensor tag with a narrowly scoped `F.linear` dispatch.
  It inserts the activation boundary for the **unchanged native experts
  forward**. There is no global monkey-patch of `torch` or `F.linear`.
- Router weights remain native parameters. Shared gate is a nonquantized
  linear binding; its sigmoid and multiplication remain in the TF MoE block.
- The model is constructed on meta; only non-adapter parameters are loaded.
  RoPE buffers are regenerated by the native TF module, never left as
  uninitialized `to_empty` data.

## Memory, reads and deadline

Before checkpoint access, the supervisor records `/proc/meminfo` and available
cgroup v1/v2 limits, including the v1 hierarchical limit. It refuses insufficient
host/cgroup headroom. Defaults:

- 8 intra-op threads, 1 inter-op thread; CUDA hidden, no distributed setup.
- 16 GiB worker `RLIMIT_AS` hard address-space cap, set after library imports
  and **before** any checkpoint/tiny-model data. The supervisor additionally
  monitors worker RSS against that cap.
- One global **256 MiB byte-bounded LRU** for all lazy linear/expert matrices.
  Matrices larger than the cache (notably the LM head) are transient, not retained.
  Live operands and conversions are additional to the cache limit and remain
  subject to the worker cap. This does not expand all 35B weights to F32.
- At most two open shard file handles. Tensor payload reads use explicit byte
  ranges, not a persistent whole-shard mmap.
- A **900-second hard wall-clock deadline** covers imports, tiny checks,
  metadata/scales, loading, forwards, hashing and output. The stdlib supervisor
  kills the worker process group even when a native call is stuck. No automatic
  retry. `run.log` and `manifest.json` retain the failure; timeout exit is 124.

`--cache-mib` allows 0..1024 MiB; `--memory-cap-gib` allows 10..32 GiB;
`--threads` allows 1..8. `--timeout` cannot exceed 900 seconds.

## Scale verification and provenance

`scale-pairs.json` inventories **every quantized text pair**. All pair dtypes,
shapes and block grids are checked. Every actual scale payload is read, checked
finite and positive, and hashed. For each weight that is actually used, all FP8
values are checked finite. Samples on both sides of 128-block boundaries verify
the numeric product: integer-BF16-RNE for `bf16_rne`, unrounded F32 for `f32`.

`source-payloads.json` records checkpoint index hash, per-shard header hashes,
file size/mtime and SHA256 for **all read payloads**. Re-reading a tensor checks
its payload hash has not changed during the run. The config, tokenizer files,
script and TF implementation also have hashes. This intentionally does **not**
read all 35B weights to hash whole shard files. Unused experts' FP8 payloads,
vision and MTP payloads are not certified.

## Artifact contract

Check `manifest.json` first. Require:

- The exact schema for the intended profile (see table above); do not accept
  the old schema for the new F32-dequant contract;
- `execution.precision_profile` and `precision_contract.profile` agree with
  `arguments.precision` for new runs. Historical manifests lacking these fields
  belong to the original BF16-RNE schema/profile;
- `status == "complete"`;
- `full_reference_complete == true` when consuming full-model results.

Tiny-only success is explicitly **not** full-model success. A failed full run
may still leave independently completed `precision-adapter.json` and
`tiny-golden.json`; do not consume unfinished full-model files as a passing run.

Each case has `<case>.json` and `<case>.safetensors`. Verify the SHA256 before
reading. JSON enumerates every tensor's dtype and shape. Safetensors values are
contiguous, row-major, with the axes below; do not transpose or normalize again.
Request IDs in the report are authoritative—do not retokenize in numerical tests.

For each stage `prefill` / `decode.0`:

- `input_ids [1,T]`, `position_ids [1,T]`, `cache_position [T]`, and
  `attention_mask [1,past+T]` (all ones).
- `logits [1,T,248320]`: **all vocabulary logits at every input position**, F32.
- `embedding`, `final_norm [1,T,H]`: actual native module outputs.
- `layers.NN.hidden [1,T,H]`: layer output after attention/MLP residuals,
  before the final model norm.
- `layers.NN.attention` and `layers.NN.moe [1,T,H]`: branch outputs.
- `layers.NN.shared_gate_logit [T,1]`: raw shared gate projection;
  the native block subsequently applies sigmoid and multiplies shared output.
- `layers.NN.selected_expert_ids [T,8]` and `routing_weights [T,8]`:
  actual router outputs, I64 and F32. Tiny uses top-k=2.

With `--cache-states`, each stage also snapshots:

- `cache.conv_states.NN [B,2*Hk*Dk+Hv*Dv,Kconv]`;
- `cache.recurrent_states.NN [B,Hv,Dk,Dv]`;
- `cache.key_cache.NN` / `cache.value_cache.NN [B,Hkv,total_tokens,Dhead]`.

Snapshots are cloned before native cache mutation. Missing entries correspond
to a different attention type, not zero-sized tensors. The real model has 30
GDN and 10 full-attention layers. Prefill predicts g0; `decode.0` **consumes g0**
and predicts g1. The final cache contains prompt+g0, not g1. Calls record exact
positions and prediction IDs. TF's later multi-token cached GDN continuation is
not certified by this script; only initial prefill followed by one-token decode.

## Golden checks and interpretation

`precision-adapter.safetensors` includes a 257x259 E4M3 byte matrix, 3x3 numeric
BF16 scales, signed RNE ties, activation, rounded dequantized weights, F32 output
and an independent F64 product/sum reference. It checks partial blocks, weight
and activation RNE, and the absence of BF16 output rounding. F32 accumulation is
compared with `atol=1e-3, rtol=2e-5` to the F64 sum for this stress fixture.

`tiny-checkpoint/` is a reusable fixed-seed, two-layer native MoE checkpoint:
GDN + full attention, 4 experts, top-k=2, shared expert and gate, split FP8
expert tensors and BF16 numeric scales. `tiny-lazy` runs the lazy adapters;
`tiny-eager` independently decodes tiny weights using an integer RNE oracle
and uses eager native TF modules. All 46 captured tensors, including routing,
GDN recurrent/conv and full-attention KV state, are compared after prefill and
one decode (`atol=rtol=2e-5`, exact integer equality). A 128 KiB LRU forces
eviction in this check. Both profiles exercise this fixture with their selected
arithmetic. The F32 golden uses independent indexed F32 dequantization and
checks that neither activation, dequantized weight nor output is BF16-rounded;
its stored matrix is named `dequant_f32` instead of `dequant_bf16_f32`.

For the new `f32` full-model contract, `consumer_comparison` records the initial
requested criterion `atol=rtol=2e-4`, computed in F64 over every finite element.
This is the starting criterion for the backend agent's CUTLASS TF32x3 comparison,
not a claim that GPU parity passed. No tolerance is silently increased.

For Ferrule comparisons, compare exact shapes and integer IDs first, then all
finite F32 elements, with metrics calculated in F64 (max/mean absolute error,
RMSE and failed-element count for an explicitly selected atol/rtol). **No
full-model Ferrule tolerance or parity is certified here.** Matching a greedy
token or top-k list alone is not sufficient. These files are an external numeric
reference for subsequent full-logit/layer-state comparisons.

## Recorded local validation

`target/validation/qwen35-fp8-reference-full40-v1/` completed in **125.50 s**
including tiny checks and scale auditing. Peak RSS was **10,521,030,656 bytes
(9.80 GiB)**, under the 16 GiB cap; cache peak was 256 MiB. It checked 30,970 text
FP8/scale pairs and sampled all 4,747 distinct quantized pairs used by the cases.

| Case | Request IDs | Prefill prediction | Decode prediction | Full logits |
| --- | --- | --- | --- | --- |
| Hello | `[9419]` | `11` = `,` | `353` = ` I` | `[1,1,248320]` twice |
| capital | `[760,6511,314,9338,369]` | `11751` = ` Paris` | `13` = `.` | `[1,5,248320]`, `[1,1,248320]` |

Each case contains 654 tensors with all 40 layers and both stages' caches.
Tiny lazy/eager maximum absolute error was 0.0 across all 46 tensors. These are
reference-generation results, **not a claim that Ferrule full-model validation
has passed**. The existing 0.8B oracle and all production files were unchanged.

### New F32-dequant profile

`target/validation/qwen35-fp8-reference-full40-f32-v1/` completed in **84.37 s**
(including imports, golden checks, pair auditing and output). Peak RSS was
**10,523,160,576 bytes (9.80 GiB)**, below the 16 GiB cap. LRU peak was exactly
256 MiB. All 30,970 text pair scales were audited and 4,753 used quantized pairs
were sample-checked. No GPU was initialized.

Hello's input `[9419]` predicted `11` (`,`), then consuming `[11]` predicted `353`
(` I`). Capital's `[760,6511,314,9338,369]` predicted `11751` (` Paris`), then
consuming `[11751]` predicted `13` (`.`). Forward times were 13.29/12.61 seconds
for Hello and 32.66/13.13 seconds for capital. The four full logits tensors
contain **1,986,560 finite F32 values**, with the same shapes and layer/route/cache
fields documented above (654 tensors per case).

All 8 original unit tests still pass; 3 new F32/profile-isolation tests also pass.
The regenerated default profile's precision golden, tiny lazy/eager outputs and
tiny checkpoint payloads are bytewise identical to those in the old full40 run.
New F32 tiny lazy/eager max_abs is also 0.0, but F32 and BF16 profile tensors differ,
as they should. Old full40 artifacts were not overwritten.

The new and old profiles happen to share greedy predictions, **not logits**:
max absolute old-vs-new differences are 0.0794321/0.0458790 for Hello and
0.2907410/0.0305109 for capital prefill/decode. These are CPU-profile differences,
not Ferrule/GPU errors or acceptance thresholds. Use the new schema and directory
for the new contract. Previously generated partial operator fixtures remain
BF16-RNE fixtures and must not be used as F32-dequant expected results.
