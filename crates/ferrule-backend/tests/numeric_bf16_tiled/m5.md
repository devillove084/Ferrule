# Frozen Capital/prefill L0 M5 QKV compatibility

## Result

The `[5,2048] @ [8192,2048].T` discrepancy is a native reduction-order
compatibility difference, not a weight decode, input, tile-addressing, or BF16
conversion bug. The explicit existing
`NumericFp8Precision::Bf16SlicedK2F32Accumulate` matches **all 40,960 native F32
accumulators and BF16 words**, with no tolerance or reference changes.

The only production change for this task is admitting multirow shapes in that
profile's Rust plan and native preflight. Its kernel math is unchanged. No
model selection, defaults, owners, persistent storage, or workspace policy
changed. Other agents' GEMV work is independent and preserved.

## Production path and numerical results

Input is packed BF16 (or F32 input rounded RNE to BF16), followed by decoded
weight tiles `BF16_RNE(F32_RN(FP8 * BF16_scale))` using global 128x128 scale
indices. The sliced kernel transposes the GEMM view, with CTA64x64x64,
warp64x32x32, MMA16x8x16, five stages, and two on-chip K32 partitions per K64
tile. The epilogue combines F32 accumulators without global split-K scratch.
Output remains F32 with full `ldd=N`, then the owner's existing BF16 RNE
writeback. Tile origin advances output by `first * sizeof(float)`, not by M.

## Executable regression and integration

`gpu::fixed_input_capital_m5_qkv_exact_sliced_k2` is ignored by default. It
requires `FERRULE_BF16_M5_DIR` (the frozen fixture),
`FERRULE_BF16_M5_NATIVE_F32` (the separately pinned accumulator diagnostic),
and `FERRULE_BF16_M5_REPORT` (a fresh report). It pins hashes, asserts the
unchanged 26-word tiled baseline, and strictly requires zero sliced BF16/F32
differences at every tile/input combination. No GPU work may run without
explicit ownership and authenticated bounded supervision.

The evidence `run.py LABEL` executes a fresh `LABEL-plan.json`, refuses an
existing supervisor receipt, checks the exact Rust test listing, records
binary/source hashes, authenticates subreaper custody, and checks three idle
GPU observations afterward. Clone a plan to a fresh label and report path to
rerun; do not overwrite an existing receipt. Rebuild after source changes.

Final exact-filter plans: `owner-final`, `graph-final`, `reject-final`,
`poison-final`, `m1-gate-final`, `m1-qkv-final`. All passed. Graph tests exercise
M=1/2/5/9/17/65, K=64/256/2048 for sliced-K2, partial tiles, nonzero scale
origins, padded strides, guards, and replay. Host/native and GPU negatives
cover zero M, invalid K/strides, null/wrapped spans, insufficient and excess
scratch, foreign owner, wrong profile, and poisoned workspace. Poison checks
inject quarantine, not a real device fault. No new unknown-completion behavior
was introduced. Both frozen M1 gate and original M1 QKV regressions pass.

Integrator action: explicitly choose `Bf16SlicedK2F32Accumulate` for this
supported M5 QKV in a Mixed plan, retaining the established M1 QKV profile.
This is not a universal HF dispatch policy; other shapes require their own
bounded compatibility evidence. No model-plan changes or full40 run were made
by this backend task. Resource ownership must remain unchanged.
