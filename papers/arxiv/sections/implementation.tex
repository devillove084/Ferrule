\section{Implementation}
\label{sec:implementation}

\subsection{Capability-scoped resource owners}
\label{sec:implemented-read-path}
The model-neutral decoder binds immutable parameter descriptors to a
materializer, expert provider, and execution operators. The materializer owns
source validation and host quota; the CUDA leaf owns device-cache admission,
scratch, uploads, and consumer completion. Capability checks select compatible
read and transfer mechanisms rather than model-specific materialization
factories. The full-model evidence covers Qwen3.5 only, not DeepSeek-V4.

This private expert path implements Algorithm~\ref{alg:bounded-lookahead}
without instantiating the general runtime resource manager or materialization
registry for these reads. Algorithms~\ref{alg:normal-materialization}
and~\ref{alg:terminal-custody} are reference contracts for its responsibilities,
not one universal call path.

The checkpoint catalog records tensor descriptors and ordered file extents.
A read plan binds filesystem identity using device, inode, length, modification
time, and change time. The worker verifies this identity before and after
positioned reads; the consumer rechecks it before constructing the three
compressed gate, up, and down artifacts. Descriptor hashes describe dtype,
shape, and extent metadata rather than authenticating every payload byte.
The worker receives neither CUDA handles nor cache leases or runtime
continuations.

Both compared schedules enable the same owner-held worker. Blocking submits
required demand and waits; lookahead carries one exact next ticket across
current compute submission. The first admitted sequence creates the worker;
clean later sequences reuse it without resetting identities or source
snapshots. Sequence completion drains unused reads and releases proved
payload/read-slot claims, but does not join. Timing boundaries and warmup
exclusions remain those declared for each experiment; reuse implies no extra
warmup procedure.

After upload, computation borrows resident device handles and immutable
binding metadata, so temporary host aliases can retire before the next read.
Kernel mathematics, selected expert order, and completed-only cache
replacement are unchanged. A pipeline-disabled path is not an equivalent
blocking control.

The principal configuration uses a 64 MiB logical host limit, including
8 MiB metadata and 2 MiB requested stack; the remaining 54 MiB is split
equally between packed and prepared quotas. With $P_{\max}=3{,}146{,}112$
bytes, Equation~\ref{eq:host-read-bound} gives 16,777,984 bytes, matching the
observed logical peak in the synchronous and grouped HTTP arms. Their idle
live-owner charge remains 10,485,760 bytes, not zero. Device cache and scratch
are separate domains; these charges do not bound total RSS.

Passive snapshots report reads, waits, charges, join state, and uncertainty
without refunding or repairing custody. Final owner teardown, rather than
sequence completion, owns the actual join. The full-model reports expose no
post-owner-drop join witness. Process reaping and idle-device observations do
not supply that witness or certify physical memory release.

\subsection{Synchronous expert transfer and serving policy}
The baseline uploads three numeric expert projections using six pageable
copies, each with its explicit completion fence. Grouped synchronous upload
uses the same six copies and source representation, but one exact
compute-stream fence covers the successful group. All six destinations and
immutable source aliases enter custody before the first possibly submitting
copy. There is no extra pinned allocation, concatenation buffer, upload
event, or polling ticket. A failed proof retains the group and source charge
and quarantines the owner; later proof cannot heal it.

CUDA 12.4.0 documents that an \texttt{Async} suffix does not unconditionally
promise host-asynchronous behavior: the arguments matter. Asynchronous copies
between pageable host and device memory may be synchronous with respect to
the host, and staging through pinned memory may also synchronize the stream.
For the documented synchronous pageable host-to-device case, return can
precede completion of the final DMA~\cite{nvidia2024cudasync}. API return,
device completion, and transfer--compute overlap are therefore distinct.
One explicit fence is not a count of all native synchronizations or evidence
of asynchronous transfer or overlap. These are code-level counts, not observed
per-request backend-call counts.

Grouping does not remove the existing last-consumer event or owner
upload-stream fence. Their redundancy has not been established for this leaf,
lookahead, or other outstanding work. The complete forward remains
synchronous; host lookahead alone does not prove hardware overlap.

With bounded reads absent or blocking, omitted transfer policy resolves to
synchronous upload. A supported bounded-lookahead configuration on the local
Mixed BF16/F32 CUDA numeric leaf instead resolves to grouped synchronous
upload; explicit synchronous selection remains a baseline. Normal serving
rejects grouped upload with blocking reads; that combination is confined to
private experiments. These current selection rules do not relabel the frozen
explicit-policy measurements on the same operator leaf or establish new
numerical-quality results.

\subsection{Other protocol implementations}
The general materialization path installs a registry only when a runner
transfers a physical provider to the resident engine. This path merges
compatible exact keys, validates completion before mutation, and separates
stage-custody return from credit release and resident-grant transfer. A separate
routed-expert provider implements pinned reads and CUDA upload/installation.
Its registered slabs retain aligned ranges and generations; tickets retain
the original event and frame after notification errors. Replacement carries
the old binding and consumer-completion evidence. This capability is distinct
from the pageable numeric expert path, not evidence of its registry coverage.

The resource broker canonicalizes and checks claims before charging them.
A later-stage budget wait retains earlier buffers and destinations. Grants
have no implicit destructor refund. The five accounting classes in
Equation~\ref{eq:credit-conservation} refine these ownership states; tested
host/cache bounds are not an integrated five-class proof.

State publication uses a separate prepared-state protocol. A provisional
journal precedes backend preparation because preparation can submit work
before returning a handle. Lost installation acknowledgments cause polling
of the same operation rather than redispatch. Exact acknowledgments precede
logical publication; displaced-state retirement and page confirmation precede
reuse. Committed KV reads revalidate owner, slot, incarnation, generation,
layout, frontier, range, and page authority. Finishing a transaction consumes
its handle custody, not every independent weight, KV page, or cache pin.

Other capabilities have separate boundaries. Host-KV placement exposes
logical read pins and admission, not a completed production DMA path; its
accepted or Unknown commands still require backend quiescence evidence.
Shared CUDA transport independently retains fixed pinned chunks and device
views until their own fences; it is not the pageable expert-upload mechanism.
Hybrid and collective paths require their own audits, not extrapolation from
single-device results. A late registry completion can close its named stage
without clearing another owner's poison, and host-worker join cannot clear
device uncertainty.
