\section{Materialization, Custody, and Bounded Scheduling}
\label{sec:design}

\subsection{Normal execution}
\label{sec:normal-profile}
A nonresident dependency moves through six stages. The adapter first freezes
a source-bound plan and obtains an exact destination reservation. The owner
then admits the read, upload, and installation claims as each stage becomes
eligible. Before any preparation can submit physical work, it records the
provisional operation and cleanup intent in a persistent journal.

A successful read returns read custody. The owner explicitly releases the
read slot and storage-read claims while retaining the host payload charge
for upload. The upload's fence ends DMA custody, but the destination remains
owned. Installation validates the new binding; replacing an old binding also
requires evidence that its previous consumers have finished. Publication
then transfers the resident grant and resolves the exact waiters. It does
not evict the newly resident bytes.

Before execution, the consumer revalidates its dependency and lease epochs
and acquires any resume claims. Consumer completion and state publication
have their own evidence. A request can finish while persistent KV state or
cached weights remain live. Figure~\ref{fig:architecture} summarizes these
roles; Section~\ref{sec:implementation} distinguishes the concrete operator
path from the more general materialization protocol.

\subsection{Safety invariants}
\label{sec:invariants}
\paragraph{Unique accounting ownership.}
For each covered domain, the intended partition is
\begin{equation}
\begin{aligned}
 b_a&=F_a+R_a+I_a+L_a+T_a,\\
 U_a&=R_a+I_a+L_a+T_a,\qquad F_a=b_a-U_a.
\end{aligned}
\label{eq:credit-conservation}
\end{equation}
Every claim belongs to exactly one class: free, reserved, provider-in-flight,
live, or retained. Different claims of one operation may occupy different
classes. Unknown claims belong to $T_a$; uncertainty does not create a second
charge. Returning custody can change ownership without reducing $U_a$.
Release or transfer is an explicit action. This is a semantic invariant of
the reference contract, not five literal implementation fields or a measured
integrated conservation proof.

\paragraph{Exact evidence before mutation.}
An event must match the operation, key, stage, generations, and byte contract
before it changes state. Success requires the full expected amount; a partial
failure is not readiness. Stale identity cannot release a newer generation's
grant. A matching event with a validated non-success outcome instead selects
cleanup for its own operation. Notifications merely trigger revalidation.

\paragraph{Reachable physical custody.}
Each outstanding physical reference remains reachable from an authoritative
owner, including after preparation or submission fails without returning a
public handle. Read return, upload completion, resident transfer, and
consumer retirement close different obligations. An address or read-only
snapshot supplies neither allocation ownership nor completion authority.

\paragraph{Publication before reuse, with distinct proofs.}
Producer success makes a candidate ready; publication also validates the
actual binding and authorization. Replacement requires old-consumer
quiescence. For prepared KV state, exact installation acknowledgments precede
logical publication, and retirement acknowledgments precede page reuse.
This ordering is a scoped in-memory lifecycle, not distributed durable commit.

\paragraph{Terminal demand preserves residual obligations.}
Accepted cancellation detaches only the terminating demand. Independent
waiters and persistent owners remain. Cancellation acceptance does not prove
quiescence or reverse an irreversible publication decision. Missing physical
proof retains the payload and charge as Unknown. A late exact completion can
close a named stage without clearing a separately poisoned physical owner.
Figure~\ref{fig:operation-state} makes the distinction between logical outcome
and resource lifetime explicit.

\subsection{Reference materialization and cleanup algorithms}
\label{sec:algorithms}
Algorithms~\ref{alg:normal-materialization} and~\ref{alg:terminal-custody}
express reference contracts for the relevant owners. Their helper names are
protocol roles, not a claim that every runner invokes one common manager.
The operation record and journal persist across calls. A pending or idle
notification is pollable only while its original obligation remains known.
\textsc{AdmitStage} checks intrinsic feasibility, canonical units, overflow,
authority, compatibility, and the policy in
Equations~\ref{eq:admission}--\ref{eq:execution-reserve}, then acquires grants
with an owner-side capacity recheck. It preserves previously held grants on
\textsf{Wait}. \textsc{SelectCleanup} records the primary reason once and
prevents later calls from restarting normal dispatch.

\begin{algorithm}[!htbp]
\caption{Progress one exact materialization operation}
\label{alg:normal-materialization}
\fontsize{9}{9.6}\selectfont
\begin{algorithmic}[1]
\REQUIRE frozen plan $P$, provider $v$, ledger $\mathcal L$, demand $\delta$, journal $J$
\ENSURE result in $\{\mathsf{Ready},\mathsf{Pending},\mathsf{Terminal}\}$; residual custody stays reachable
\STATE \textbf{Persistent state:} operation $o$, its stage $s$, grants, and original tickets
\IF{cleanup is selected or $o$ retains Unknown}
  \STATE continue only Algorithm~\ref{alg:terminal-custody}; \algorithmicreturn{} $\mathsf{Terminal}$
\ENDIF
\WHILE{$o$ is not resident}
  \IF{$o$ is installed}
    \STATE $p\gets\operatorname{PublicationPreflight}(o)$
    \IF{$p=\mathsf{Ready}$}
      \STATE publish exact binding; transfer resident grant; resolve exact waiters
      \STATE retire load once; mark $o$ resident
    \ELSIF{$p=\mathsf{Blocked}$}
      \STATE retain binding and grants; arm replacement-custody revisit
      \RETURN $\mathsf{Pending}$
    \ELSE
      \STATE $\operatorname{SelectCleanup}(J,o,p)$; \algorithmicreturn{} $\mathsf{Terminal}$
    \ENDIF
  \ELSE
    \STATE $s\gets o.\mathit{stage}$
    \IF{$s$ is not submitted}
      \STATE $\alpha\gets\operatorname{AdmitStage}(P,s,\mathcal L,\delta)$
      \IF{$\alpha=\mathsf{Rejected}$}
        \STATE $\operatorname{SelectCleanup}(J,o,\alpha)$; \algorithmicreturn{} $\mathsf{Terminal}$
      \ELSIF{$\alpha=\mathsf{Wait}$}
        \STATE retain held grants; arm admission revisit; \algorithmicreturn{} $\mathsf{Pending}$
      \ENDIF
      \STATE journal stage custody before $\operatorname{SubmitOnce}(v,o,s)$
      \IF{submission fails or its disposition is ambiguous}
        \STATE retain original payload and claims; select cleanup; \algorithmicreturn{} $\mathsf{Terminal}$
      \ENDIF
    \ENDIF
    \STATE $e\gets\operatorname{PollOriginal}(v,o,s)$
    \IF{$e$ is pending or idle and the original obligation is known pollable}
      \STATE arm completion revisit; \algorithmicreturn{} $\mathsf{Pending}$
    \ELSIF{$e$ mismatches identity, stage, generations, or byte contract}
      \STATE reject without mutation; retain original obligation and revisit
      \RETURN $\mathsf{Pending}$
    \ELSIF{$e$ is pending/idle without that proof, a provider fault, or lacks physical proof}
      \STATE retain Unknown; select cleanup; \algorithmicreturn{} $\mathsf{Terminal}$
    \ENDIF
    \STATE apply exact stage-custody return once; retain residual claims
    \IF{$e$ reports validated non-success}
      \STATE $\operatorname{SelectCleanup}(J,o,e)$; \algorithmicreturn{} $\mathsf{Terminal}$
    \ELSIF{$s=\mathsf{Read}$}
      \STATE release read-slot/read-byte claims; retain host payload charge
      \STATE advance to upload; clear only completed read ticket
    \ELSIF{$s=\mathsf{Upload}$}
      \STATE release upload and host claims after exact fence; retain destination
      \STATE advance to install; clear only completed upload ticket
    \ELSE
      \STATE mark $o$ installed
    \ENDIF
  \ENDIF
\ENDWHILE
\RETURN $\mathsf{Ready}$
\end{algorithmic}
\end{algorithm}

Publication preflight distinguishes a live-custody block from an invalid
binding. Rejection after installation preserves the journal and physical
binding for cleanup; it does not undo the installation. A terminal load
result likewise does not mean physical closure. Journaled returns and
releases are applied once, even if a subsequent cleanup step fails.

A terminal pass operates on a finite worklist $\Omega$ of obligations
reachable through $J$ after demand detachment. The persistent cursor $w$
and unvisited cohort prevent unresolved entries at the front from hiding
later entries. New obligations cannot overtake that cohort. Removing an
entry from the local worklist never removes it from its authoritative owner.
A custody handoff takes effect only after acknowledgment by the new owner.

For each exact operation and stage, cancellation marker $\mu_o[s]$ is one of
\textsf{None}, \textsf{Pending}, \textsf{Submitted}, or \textsf{Uncertain}.
It also binds the key and generations. Known non-acceptance permits an
owner-authorized retry with the original arguments; acceptance permits only
polling. An ambiguous reply latches uncertainty and cannot be retried as
though cancellation had been rejected. A different stage has a different
marker. Safe discard of an unsubmitted reservation follows the same rule
when it requires provider cancellation.

\begin{algorithm}[!htbp]
\caption{One bounded terminal-custody pass}
\label{alg:terminal-custody}
\fontsize{9}{9.6}\selectfont
\begin{algorithmic}[1]
\REQUIRE journal $J$, terminal intent $i$, visit limit $k>0$
\ENSURE caller outcome $y$ and custody status $h$; unresolved ownership persists
\STATE \textbf{Persistent state:} worklist $\Omega$, cursor $w$, exact cancellation markers $\mu_o[s]$
\IF{$i$ requests cancellation and the terminal owner rejects it}
  \RETURN current outcome and custody status
\ENDIF
\STATE latch accepted $y$; detach terminating demand once; preserve irreversible intent
\STATE $\Omega\gets\operatorname{ResumeOrSnapshot}(J,w)$; $n\gets\min(k,|\Omega|)$
\WHILE{$n>0$}
  \STATE $o\gets\operatorname{Pop}(\Omega)$; $s\gets o.\mathit{stage}$; $n\gets n-1$
  \IF{another waiter or persistent owner still holds $o$}
    \STATE preserve shared load or acknowledged handoff; do not cancel or refund
  \ELSIF{$o$ has persistent physical-owner Unknown}
    \STATE retain payload, charge, and poison; block reuse
    \STATE apply any late exact stage completion only to its named obligation
  \ELSIF{$o$ is positively unsubmitted}
    \STATE attempt safe discard once under $\mu_o[s]$
    \STATE discharge eligible claims only with exact discard proof
  \ELSE
    \STATE $e\gets\operatorname{ObserveOriginalOnce}(o)$
    \IF{$e$ mismatches the exact completion contract}
      \STATE reject without mutation; preserve $o$
    \ELSIF{$e$ proves named stage-custody return}
      \STATE journal the return once; advance original cleanup at most once
      \STATE preserve primary outcome and residual custody on any cleanup error
      \STATE release only proved claims; confirm retirement before reuse
    \ELSIF{$e$ is pending and the original obligation is known pollable}
      \IF{cancellation is legal and $\mu_o[s]\in\{\mathsf{None},\mathsf{Pending}\}$}
        \STATE $\gamma\gets\operatorname{CancelOnce}(o,\mu_o[s])$
        \IF{$\gamma=\mathsf{Accepted}$}
          \STATE $\mu_o[s]\gets\mathsf{Submitted}$; await physical completion
        \ELSIF{$\gamma=\mathsf{NotAccepted}$}
          \STATE $\mu_o[s]\gets\mathsf{Pending}$; retain exact retry arguments
        \ELSE
          \STATE $\mu_o[s]\gets\mathsf{Uncertain}$; retain Unknown; prohibit retry
        \ENDIF
      \ENDIF
    \ELSE
      \STATE retain payload and journal; classify held claims in $T_a$ without recharging
    \ENDIF
  \ENDIF
  \STATE advance $w$ past $o$; defer unresolved entries behind unvisited entries
  \STATE arm exact completion, cleanup, or owner-progress revisit
\ENDWHILE
\STATE persist unvisited $\Omega$, cursor, and all unresolved owner records in $J$
\IF{no unvisited or unresolved custody remains}
  \STATE $h\gets\mathsf{Closed}$ for this bookkeeping scope
\ELSIF{physical-owner Unknown remains}
  \STATE $h\gets\mathsf{UnknownRetained}$
\ELSE
  \STATE $h\gets\mathsf{Pending}$; schedule a later pass
\ENDIF
\RETURN $(y,h)$
\end{algorithmic}
\end{algorithm}

Algorithm~\ref{alg:terminal-custody} visits at most $k$ obligations, with at
most one observation and one cleanup advancement per visited item. This
bounds work per pass, not provider-call latency or total cleanup time.
A secondary error preserves the primary reason, original phase and arguments,
and partial returns already recorded. Cleanup remains pending only while its
original obligation is known pollable; otherwise it becomes Unknown.
Neither a wake nor an unrelated later fence authorizes reuse. Clearing a
poisoned physical owner would require a separately established teardown or
isolation boundary, which these algorithms do not supply.

\subsection{Bounded next-expert lookahead}
\label{sec:bounded-lookahead}
Algorithm~\ref{alg:bounded-lookahead} describes the implemented synchronous
expert-operator schedule. A bucket binds an expert to its selected token
rows; the operator preserves the existing bucket order. Let $H$ be its logical host-staging limit,
$P_{\max}$ the largest selected expert's packed weights and scales, $M$ the
metadata allowance, and $S$ the requested worker-stack reservation. Both
schedules require
\begin{equation}
 2P_{\max}+M+S\leq H
 \label{eq:host-read-bound}
\end{equation}
before starting the worker. The factor two covers packed/prepared coexistence,
not two permanent expert copies. During execution the charged occupancy is
\begin{equation}
 C_{\mathrm{host}}(t)=B_{\mathrm{packed}}(t)+B_{\mathrm{prepared}}(t)
                    +M(t)+S(t)\leq H.
 \label{eq:host-logical-charge}
\end{equation}
Packed quota covers queued, in-flight, and held completions. Prepared quota
remains charged while any weight or scale alias survives. Aliases do not add
copies, and dropping one alias does not release the remaining allocation.
Retained Unknown is already included in these charges. One worker, a queue
of depth one, and two charged read slots bound the outstanding host work.

\begin{algorithm}[!htbp]
\caption{Bounded next-expert reads in a synchronous forward}
\label{alg:bounded-lookahead}
\fontsize{9}{9.6}\selectfont
\begin{algorithmic}[1]
\REQUIRE ordered selected buckets $\mathcal B$, source-bound plans,
         mode $m\in\{\mathsf{Blocking},\mathsf{Lookahead}\}$, limits $H,M,S$
\ENSURE unchanged bucket order and device proofs; residual custody retained
\STATE validate three-artifact plans and Equation~\ref{eq:host-read-bound}; start the same worker
\STATE \textbf{State:} at most one next ticket $\tau$, exact deferred error, payload-alias charges
\FOR{current bucket $b$ in $\mathcal B$}
  \STATE admit and pin current device residency and scratch; validate source
  \IF{current expert is not resident}
    \STATE drain unrelated speculation by its original identity
    \STATE honor any error deferred for $b$ before new dispatch
    \IF{no exact carried ticket for $b$}
      \STATE $\tau\gets\operatorname{SubmitExact}(b)$ under read-slot and byte limits
    \ENDIF
    \STATE await original $\tau$; blocking waits immediately after submission
    \IF{worker custody is Unknown}
      \STATE retain identity, charge, and poison; return through terminal cleanup
    \ENDIF
    \STATE take completion once
    \STATE Validate the original operation, prepared source-image identity, selected expert,
    \STATE \hspace{1em}read plan, byte count, and source freshness.
    \IF{evidence mismatches or reports non-success}
      \STATE preserve primary error and residual custody; return through terminal cleanup
    \ENDIF
    \STATE reserve prepared quota while packed bytes remain charged
    \STATE construct gate/up/down artifacts without rereading; track payload aliases
    \STATE upload current expert under destination-generation checks and CUDA proofs
  \ENDIF
  \STATE drain speculation made redundant by a current resident hit
  \STATE release current host charge only after payload-alias retirement
  \STATE inspect next selected bucket without pinning it or changing replacement order
  \IF{$m=\mathsf{Lookahead}$ and next expert is nonresident and host custody permits}
    \STATE try one next read before current compute submission
    \STATE defer speculative submission or read errors to that exact later demand
  \ENDIF
  \STATE submit current computation from resident device handles
  \STATE consume output under its lease; preserve existing fences and retirement
\ENDFOR
\STATE on scope end or error, cancel unused reads, drain, and join the original worker
\STATE retain Unknown and alias-held quota; host join does not discharge device custody
\end{algorithmic}
\end{algorithm}

Read completion validates the prepared source image, not a device destination
generation. Destination binding and reuse checks remain with upload and
consumer ownership. The residency hint is read-only: it neither pins the next
expert nor alters replacement order. Speculative failure becomes relevant only if that exact
expert is later demanded. Unused reads are drained and counted as wasted
work; lookahead is therefore permitted to read more than blocking, although
it does not do so in the paired experiment. Cancellation cannot interrupt an
already executing synchronous file read. The owner still waits for its
existing consumer proofs, so the complete forward remains synchronous.

Weak liveness witnesses track prepared allocations without adding payload
copies. Strong aliases retain quota; after their final retirement, weak
control blocks and allocator-retained memory can still occupy physical
memory. Thus quota release and RSS reduction are separate observations.
