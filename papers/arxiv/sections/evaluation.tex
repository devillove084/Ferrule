\section{Experimental Methodology}
\label{sec:eval-setup}

\subsection{Model, configuration, and quality criteria}
The serving experiments use Qwen3.5-35B-A3B-FP8 with text-only execution on
one CUDA device: pipeline, tensor, and expert parallelism are each one.
Experts are materialized lazily and KV state remains resident. The Mixed
profile uses BF16 activations, KV, and convolution state, with F32 accumulation
and state-space-model state. Checkpoints reside on a shared NFS mount.
The original five-pair read-scheduling study, its pressure sweep, read--compute
captures, and HTTP-cancellation experiment share one frozen serving executable.
The later persistent-worker, grouped-transfer, and HTTP-policy experiments
are separate experiment families, with separately frozen application and
control identities (Table~\ref{tab:experiment-families}). They are not
additional runs of that executable. Component faults use a small test
executable. The artifact guide records source, binary, and control identities;
source identity alone does not transfer numerical or performance acceptance.

\paragraph{Platform and observation.}
The serving experiments use one NVIDIA GeForce RTX 3090 with 24 GiB of
physical device memory. A same-boot post-hoc inventory associated with the
paired study reported an Intel Xeon Platinum 8369B at 2.90 GHz, 128 visible
logical CPUs, and 754.913 GiB of kernel-visible memory on x86-64 Linux
4.19.91; experiment-time affinity, cgroup limits, and unchanged hardware
configuration were not established. The observer sequentially samples device-wide GPU
memory and process-tree RSS/PSS, then waits 2 s. For samples wholly within
request phases, including inter-request gaps, start-to-start intervals are
2.261--2.377 s in the
paired study and 2.276--2.368 s in the pressure study; collection adds time
to the nominal wait. Whole-lifecycle maxima use 49--54 samples per paired
arm and 36 per pressure point, not continuous or uniform-rate observations.

Table~\ref{tab:paired-config} gives the original five-pair configuration.
Within that older experiment, the two arms change only the read schedule.
Both retain the same source checks, arithmetic,
cache policy, worker, consumer proofs, and synchronous forward. Runtime
profiling is disabled for ordinary timings; the separate overlap captures
enable it. Logging is identical between timing arms. No experiment flushes
page or NFS caches, and a fresh server is not assumed to have cold storage.

\paragraph{Independent reference.}
Numerical references use Hugging Face eager model forwards from Transformers
5.5.3 and Torch 2.13.0+cu129, independently of Ferrule's execution kernels.
FP8 checkpoint values and BF16 scales are decoded in F32 and rounded to BF16
execution weights, with BF16 activations and KV state and explicitly
preallocated F32 SSM state. This is decoded-storage BF16 execution, not the
stock dynamic-FP8 quantizer or default SSM-cache precision. Exactly equal
raw routing logits are resolved deterministically by lower expert ID;
distinct-logit selections and native F32 routing probabilities and weights
remain unchanged. Full-forward tests use a frozen two-prompt reference;
retained-state tests and HTTP canaries use a separately generated three-prompt
reference with the same pinned HF implementation and precision policy.

Quality is checked at two levels. Factory tests compare the model's numerical
outputs with these references using tolerance
$0.00025+0.012|\mathrm{reference}|$, with exact generated-ID checks where
observed. They cover the complete 40-layer forward, retained fresh-state
execution, ordinary execution without diagnostic observers, and cold-owner
execution in both schedules, plus a small constructor/provider check.
Factory tests and the serving executable are distinct, so HTTP observations
supply the serving-quality evidence rather than inheriting numerical
acceptance from source identity alone.

For HTTP requests, we join actual worker-enqueued token IDs to request
identities, emission ordinals, terminal usage, and complete server-sent-event
(SSE) responses. IDs are not inferred by retokenizing text. An SSE content
event is not necessarily a token boundary. In the original serving study,
eight-token requests must match the frozen ID,
text, and usage references; two-token smoke requests check length and usage
only. The original read--compute and pressure requests use those same criteria
within their stated sets. The later public-CLI acceptance and HTTP-policy pilot
instead check exact IDs, text, finish reason, usage, and request/EOS semantics
for all outputs, including the two-token Hello request. EOS stopping remains
enabled; QA happens to produce eight actual completion tokens, not an
imputed eight-token normalization.

\paragraph{Later HTTP-policy pilot.}
Each arm starts a fresh server and executes 12 serial requests: four initial
checks, one excluded QA, two QA warmups, and five measured QA requests.
Within each read schedule $r$, two paired blocks compare synchronous ($S$)
with grouped synchronous ($G$) transfer; both arms retain equal observed
logical work and exact outputs. Let $s_{krpj}$ be client send time,
$c_{krpj}$ the first nonempty SSE content event, $e_{krpj}$ client terminal
time, and $d_{krpj}$ dispatch time. Define
\begin{equation}
\begin{aligned}
 F_{krp}&=\operatorname{median}_{j=1}^{5}(c_{krpj}-s_{krpj}),\\
 E_{krp}&=\operatorname{median}_{j=1}^{5}(e_{krpj}-s_{krpj}),\\
 W_{krp}&=\max_j e_{krpj}-\min_j d_{krpj},\qquad
 Q_{krp}=\frac{\sum_j n^{\mathrm{qualified}}_{krpj}}{W_{krp}},\\
 R_{kr,X}&=\frac{X_{krG}}{X_{krS}},\qquad
 \widetilde R_{r,X}=\operatorname{median}_{k=1,2}R_{kr,X},
 \quad X\in\{F,E,Q\}.
\end{aligned}
\label{eq:http-policy-estimator}
\end{equation}
Here $n^{\mathrm{qualified}}$ counts actual reference-qualified completion
tokens. TTFT is client first \emph{nonempty content}, not first GPU-token
latency. Phase $W$ includes inter-request gaps and failures; qualification
requires the entire lifecycle and both paired arms, rather than dropping
unsuccessful slots. All observed measured completions contain eight tokens.
The analysis unit is the paired block, not the 40 measured requests.
The median of two ratios is their arithmetic mean, not a median-log estimate.
We show both pair points and no confidence intervals or significance test.
Startup is excluded. The separate serialized service rate
$40/\sum_j(e_{krpj}-s_{krpj})$ excludes gaps and must not be called phase-wide
goodput. Neither rate measures concurrent serving throughput.

\paragraph{Original read-scheduling estimator.}
Five paired blocks use the fixed order B--L, B--L, L--B, L--B, B--L, where
B is blocking and L is lookahead. Each arm starts a fresh server and executes
12 requests: four initial checks, one excluded QA request, two QA warmups,
and five measured QA requests. Thus 50 measured requests are nested within
ten lifecycles and five paired analysis units. The protocol fixes the
workload, order, time limits, and all-five-pairs-or-no-aggregate rule before
collection. It permits no retries, replacement pairs, extra warmups, or
pooled profiling timings.

For block $i$, mode $m$, and measured request $j$, client end-to-end time
$t_{imj}$ runs from send to response EOF. Time to first content $f_{imj}$
(often called TTFT) runs from send to the first nonempty SSE content event.
The arm summaries and paired estimator are
\begin{equation}
\begin{aligned}
 E_{im}&=\operatorname{median}_{j=1}^{5}t_{imj},&
 F_{im}&=\operatorname{median}_{j=1}^{5}f_{imj},\\
 G_{im}&=\frac{40\ \text{qualified tokens}}{\sum_{j=1}^{5}t_{imj}},&
 \widehat R_X&=\exp\!\left(\operatorname{median}_{i=1}^{5}
       \ln\frac{X_{iL}}{X_{iB}}\right),\quad X\in\{E,F,G\}.
\end{aligned}
\label{eq:paired-estimator}
\end{equation}
End-to-end latency is primary; TTFT and goodput are secondary. $G$ is a
qualified serial request-window rate, excluding startup and inter-request
gaps, not concurrent server throughput. The descriptive resampling procedure
enumerates all $5^5=3{,}125$ ordered paired-block resamples and exponentiates
the median log ratios at nearest ranks 79 and 3047. It does not treat
individual requests as independent replicates.

\subsection{Original complementary experiments and observation scope}
Three fresh blocking lifecycles jointly vary cache entries and byte ceilings
in fixed order: 8 entries/64 MiB, 64/320 MiB, and 128/640 MiB. Each executes
one two-token smoke and three eight-token canaries: QA, arithmetic, and
Chinese. This is a coupled-budget sensitivity study, not independent entry
and byte ablations. The new points receive HTTP/ID checks, not a transfer of
full-logit, route, or state qualification.

The overlap experiment captures one fresh QA request per schedule, separately
from the timing pairs. It correlates worker read envelopes, contained
positioned-read system-library calls, and actual expert kernels on the
profiler's common clock. The component experiment crosses two schedules
with clean failure and withheld completion proof in a two-layer numerical
fixture. It executes real reads, uploads, and CUDA computation. The HTTP
cancellation experiment instead uses the complete model: it disconnects
after the first nonempty content event and then issues a new recovery request
in the same process.

\paragraph{Interpretation boundary.}
The measurements answer different questions rather than composing into one
universal guarantee. Logical charges are not RSS or certified physical peaks;
shared NFS counters are not request-exclusive backend traffic; and component
failure checks are not full-model fault conservation. The original scheduling estimate is
descriptive at $n=5$; the later policy pilot has only two pairs per schedule: shared cache state leaves cross-block independence
unestablished, so its ranges are not guaranteed-coverage confidence intervals
or significance tests. Table~\ref{tab:evidence} consolidates the main
availability limits; the results below retain each measurement's units and

\section{Evaluation}
\label{sec:evaluation}
\label{sec:core-rqs}

The current engineering evidence supports persistent read ownership and
bounded grouped transfer, but not a uniform latency improvement. We report
those results separately from the older read-scheduling contrast, logical
I/O observations, and failure experiments. Each comparison retains its own
workload, acceptance criteria, and observation scope.

\subsection{RQ1: Bounded completion and cache-budget sensitivity}
\label{sec:rq1}
\label{sec:current-quality}

\subsection{RQ2: Equal logical demand and limited storage attribution}
\label{sec:rq2}
In the original five-pair study, blocking and lookahead perform identical
observed logical reader work in every paired lifecycle, while the available
filesystem observations do not
identify physical backend traffic. For request $q$, let $\mathcal V_q$ be
its anchored decoder invocations and define
\begin{equation}
 L_q=\sum_{v\in\mathcal V_q}\Delta_v B_{\mathrm{read}},\qquad
 H_q=\sum_{v\in\mathcal V_q}\Delta_v B_{\mathrm{upload}},\qquad
 \Delta_q=H_q-L_q.
 \label{eq:request-io}
\end{equation}
Here $B_{\mathrm{read}}$ counts logical checkpoint-reader bytes and
$B_{\mathrm{upload}}$ counts bytes requested through the host-to-device copy
interface, not physical bus traffic. The 1,020 invocation records reconcile
with owner-lifetime totals and the shutdown ledger. High-water gauges are
maxima, never summed deltas.

\paragraph{Current HTTP-policy pilot: a mixed outcome.}

\paragraph{Grouped mechanism, not a causal timing decomposition.}
Separately qualified partial process captures for both schedules observe
382,743 native \texttt{cuStreamSynchronize} calls for synchronous transfer
versus 257,163 for grouped: $-125{,}580/25{,}116=-5$ calls per logical cache
upload (Figure~\ref{fig:current-transfer-mechanism}a). Each pair retains equal
ordered logical work and output fingerprints. Observed H2D counts and bytes
are unchanged at 195,985 copies and 82,512,273,944 bytes, and observed kernel
names/counts match (409,411 kernel rows). Normalizing process totals by
25,116 logical uploads does not isolate an expert range or its elapsed cost.
Native host-duration sums cannot be interpreted as causal client-latency gains.

Blocking and lookahead captures use separate observer-control stages but the
same frozen application; each qualified pair uses a common control within
its own stage. The original four-capture stage remains failed; the later
qualified lookahead pair does not repair its rejected capture or create a
single successful four-capture stage. These are selected-model,
process-wide partial observations, not full traces. Drop counts remain
unknown, not zero, and absence of an API row is not evidence of zero calls.

The earlier grouped whole-test comparison has eight unprofiled pairs (four
per schedule), with grouped/synchronous median elapsed ratios 0.96133 and
0.96110, approximately 3.9\% lower. Its planned profiling stage failed;
it is not a 24/24 success. Libtest elapsed includes construction, checks,
I/O, and teardown: it is neither TTFT nor request latency, and is not pooled
with the HTTP pilot or profiled durations.

\paragraph{Rejected retained-upload alternative.}
The archived alternative is slower in all eight whole-test pairs: median
retained/synchronous ratios are 1.5451 for blocking and 1.5649 for lookahead
(54.51\% and 56.49\% more elapsed time). Separate partial captures observe
host-pin allocations and frees increasing from two to 25,118 each, with
extra pin/free host-duration sums of approximately 29.85 s and 29.47 s
(Figure~\ref{fig:current-transfer-mechanism}b). These sums may overlap and
are not an exclusive causal explanation of the unprofiled regression.
The negative data remain archived; retained upload is removed from the
production design, not recommended as its implementation.

\paragraph{Older five-pair read-scheduling contrast.}

\subsection{RQ4: Abort, uncertain custody, and HTTP cancellation}
\label{sec:rq4}
The original component and cancellation experiments retain their own frozen
configuration; they do not qualify later transfer-policy fault paths.
Clean component failures preserve committed state and permit a checked retry;
withheld completion proof instead retains device charges and blocks unsafe
reuse. Separately, a real HTTP disconnect reaches a cancelled worker outcome,
after which a new request in the same process matches its eight-token oracle.
These results test different boundaries of the lifetime contract.

\paragraph{Real-CUDA component failures.}
Both blocking and lookahead preserve committed state after clean abort and
retain device charges after completion-proof discard. These four component
cases use a small fixture with two
layers, four experts per layer, hidden and expert-intermediate dimensions of
16, and a vocabulary of 32. It uses FP8 weights with BF16 scales and the Mixed
arithmetic profile. Its cache has one entry and a 65,536-byte logical limit;
host staging has a separate 2 MiB limit.

The injected boundary follows a real routed-expert output submission.
For the clean case, a scheduled software error is handled with valid
completion evidence. For the Unknown case, the fixture first successfully
waits for the actual compute event and upload synchronization, then deliberately
discards that proof. This tests the response to missing authority, not a
failed driver, hung device, or physically lost event.

After clean abort, committed recurrent-state and KV contents remain unchanged,
transient resources are released, and retrying the same continuation succeeds
before its test transaction is aborted. After proof discard, repeated abort
and independent waits do not clear the poisoned owner. Its logical cache
retains 6,918 bytes of the 65,536-byte limit: 774 pending-upload bytes and
6,144 scratch bytes, all classified within the retained Unknown subset.
That subset is not an additional charge. Host cleanup reaches zero logical
charge in both schedules, illustrating that host and device custody are
different domains. Device state contents after Unknown are unobserved rather
than assumed equal. Table~\ref{tab:failure-results} summarizes the distinction.

\paragraph{Full-model HTTP cancellation.}
The client closes its connection after receiving the first nonempty SSE
content event. The matching worker terminal is observed 0.6680 s later with
cancellation accepted and submitted, rather than natural maximum-length
completion. The worker enqueues one token for the cancelled request. This
deliberately censored request has no complete client usage or successful QA outcome.
Only after cancellation acceptance does the client issue a new request and
session in the same resident process. That request delivers all eight
expected IDs, text, usage, and terminal evidence. It is fresh-request
recovery, not continuation of the cancelled request.

The owner records 5,116 completed and verified read operations with zero
cancelled or uncertain reads. Thus cancelling the HTTP request does not imply
that an individual synchronous source read was interrupted. At shutdown,
logical host charge and observed pending operations are zero; device-cache
charge is 209,739,776 bytes with residency retained. Per-request KV/frontier
snapshots and a before/after pending-operation ledger are unavailable.

Across the ten paired serving lifecycles, the owners also report known local
closure with retained residency and zero final logical read charge. Process
drain and idle observations complete supervision, but do not certify final
physical release. The component cache equations are not measurements of the
runtime broker's five-class invariant in
Equation~\ref{eq:credit-conservation}; integrated serving conservation under
faults remains unverified.

\subsection{Reproducibility}
The supplementary materials contain family-specific frozen configurations, request
references, provenance inventories, public measurement projections, and
offline checkers. They reconstruct all paired arms, token-to-response joins,
logical counters, shared-client observations, and descriptive resamples, as
well as the separate pressure, overlap, and cancellation results. Figure
inputs derive from those records. Appendix~\ref{sec:historical-chronology}
explains why earlier incomplete studies and unmatched supplements do not
contribute to the reported denominators. The accompanying artifact guide
maps each result to its inputs and checks, distinguishing public offline
verification from rebuilding or rerunning with external artifacts. The current
CPU figure renderer checks pinned canonical JSON, exact HTTP references and
raw receipt hashes, the four acceptance stats snapshots, pair denominators,
and the recorded rendering/font environment without changing the older
five-pair renderer. Raw local traces, binaries, and checkpoint payloads are
not made public merely by publishing their hashes.

\paragraph{Limits and conditional claims.}
The evidence supports these tested workloads and source-bound configurations,
not a universal resource or performance guarantee. Logical charge is not
physical peak memory, a fresh server is not cold NFS, and process drain is
not final-worker-join or universal CUDA-release proof. Conditional lifetime
proofs retain their stated source-identity and completion-authority
assumptions. Component withheld-proof checks do not establish full-model
Unknown recovery, and acceptance does not transfer to an unmeasured source
configuration. Neither unmatched resident observations nor the HTTP pilot
close the matched-vLLM comparison gap or establish a state-of-the-art
ranking. Other models remain untested.
