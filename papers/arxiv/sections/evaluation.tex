\section{Evaluation: Qualified Bounded Residency and Paired Scheduling}
\label{sec:evaluation}
\label{sec:core-rqs}
\label{sec:eval-setup}

The primary evidence is the completed \texttt{mapfixed-20261015-01} study:
five preregistered paired blocks, ten fresh server lifecycles and 120 serial
HTTP requests. Both arms execute the same CLI, SHA-256
\texttt{7cc8e0ff\ldots e607a01}, built from \texttt{86c58a0} (1,484 archived
source members). Only \texttt{--expert-read-schedule} changes. We first
establish factory and serving quality, then bounded accounting and equal
logical work, before interpreting latency and waiting. Historical failures,
the earlier disabled-pipeline plots and unmatched resident comparisons remain
separate in Appendix~\ref{sec:historical-chronology}.

\paragraph{Actual HTTP quality and complete denominators.}
All ten lifecycles and all 120 requests complete successfully; failed,
censored and unissued request counts are zero. Each lifecycle executes four
initial requests, one excluded QA request, two QA warmups and five measured
QA requests. Thus 50 measured QA requests are nested in ten arms and five
blocks, not 50 independent repetitions. Of all requests, 110 match their
exact eight-token oracle; ten two-token smoke requests have usage/length
checks only. All 900 generated token IDs are actual worker-enqueue records,
joined by worker/HTTP identities, emission ordinals, terminal usage and
SSE/DONE evidence. They are not token IDs exposed by the client API or
retokenized text. Enqueue is not client consumption; the positive terminal
joins establish delivery for these successful requests. SSE content events
are not token boundaries. Serving logits/routes/states were not measured.

\paragraph{Bounded observations, not a capacity frontier.}
Every lifecycle's logical host-reservation high-water is
\begin{equation}
  2(3{,}146{,}112)+8{,}388{,}608+2{,}097{,}152
  =16{,}777{,}984<67{,}108{,}864\ \mathrm{bytes}.
  \label{eq:qualified-host-charge}
\end{equation}
This tests the covered contract in Equations~\ref{eq:host-read-bound}
and~\ref{eq:host-logical-charge}, not RSS. Every arm's selected-device sampled
maximum is 4,125 MiB against the 7 GiB policy, with 49--54 samples per arm.
It is not a continuous peak or exact process-owned GPU attribution. Host
PSS, logical reservations and device maxima are neither interchangeable nor
summable into one working-set peak (Equation~\ref{eq:working-set}). This
closes a quality-qualified configured-budget point. A budget frontier,
complete physical attribution and compact-residency impossibility remain
unmeasured; physical-memory insufficiency and storage necessity are not claimed.

\subsection{RQ2: Identical logical work and scoped client I/O}
\label{sec:rq2}
For request $q$, anchored invocation deltas define
\begin{equation}
\begin{aligned}
 L_q&=\sum_{v\in\mathcal V_q}\Delta_v\mathrm{reader\_bytes},\\
 H_q&=\sum_{v\in\mathcal V_q}\Delta_v\mathrm{facade\_H2D\_bytes},\qquad
 \Delta_q=H_q-L_q.
\end{aligned}
\label{eq:request-io}
\end{equation}
Across all 1,020 invocation records (102 per lifecycle), both modes perform
the same observed logical work (Table~\ref{tab:paired-work}). Each pipeline
operation can cover multiple positioned reads: 40,943 verified operations
are distinct from 245,658 checkpoint-reader calls. Lifetime totals are
reconciled against invocation deltas and the shutdown ledger; peak gauges
are maxima, never summed deltas. Equal aggregate work is not a full
route-ID signature or a cache-miss equivalence proof.

\paragraph{What reached the shared client.}
The archive includes 120 request-window and 30 lifecycle-phase NFS deltas.
For P1 blocking, the enclosing request phase records 314,825,320 bytes
in the shared-client server-read counter (\texttt{serverreadbytes}). Its
individual request windows sum to 312,732,264 bytes.
The 2,093,056-byte gap lies between those windows inside the phase and is
not attributed to requests. The other nine request phases record zero.
Neither zero nor a positive shared-mount delta establishes request-exclusive
network traffic, NAS cache misses or physical backing-disk reads. Fresh
servers do not flush page/NFS caches. No storage-cold or NAS-bandwidth claim
follows. There are also 240 PID/birth-bound request I/O snapshots (120 deltas),
but startup/shutdown PID-I/O snapshots were not collected: those fields
remain null, not zero or retrospectively reconstructed. Startup logical-reader
bytes are also unobserved. Figure~\ref{f:paired-accounting} keeps these scopes
separate. RQ2 is answered at the logical and shared-client levels, with
physical backend traffic explicitly unknown.

\subsection{RQ3: Lower observed waiting under the same budgets}
\label{sec:rq3}
\paragraph{Prespecified design and estimator.}
The five paired analysis blocks retain order B--L, B--L, L--B, L--B,
B--L (B: blocking; L: lookahead), a fixed 3:2 balance, with a fresh server per
arm. The independent map-fixed generation uses the readiness-map validator
from \texttt{7d3bee2}, not a new CLI or an adaptive execution plan. The
7,200 s absolute envelope, 650 s lifecycle bound, 100 s final reserve and
all-five-pairs-or-null rule were frozen before collection. No retries,
replacement pairs, extra pilot/warmup requests, cache flushes or profiling
timings enter the study. Recorded study elapsed time is 1,519.725 s;
launch-to-ready probes span 12.847--13.247 s and are excluded from request
latency. Both earlier stopped studies retain their original null aggregates
(Appendix~\ref{sec:paired-startup-failure}).

For block $i$, mode $m$ and its five measured requests $j$, define client
E2E $t_{imj}$ as send-to-EOF and TTFT $f_{imj}$ as send-to-first-nonempty SSE
content. The arm summaries and paired estimator are
\begin{equation}
\begin{aligned}
 E_{im}&=\operatorname{median}_{j=1}^{5}t_{imj},\qquad
 F_{im}=\operatorname{median}_{j=1}^{5}f_{imj},\\
 G_{im}&=\frac{40\ \text{qualified tokens}}{\sum_{j=1}^{5}t_{imj}},\\
 \widehat R_X&=\exp\!\left(\operatorname{median}_{i=1}^{5}
        \ln\frac{X_{iL}}{X_{iB}}\right),\quad X\in\{E,F,G\}.
\end{aligned}
\label{eq:paired-estimator}
\end{equation}
$G$ is qualified serial request-window goodput, not concurrent server
throughput or startup-inclusive completion rate. It uses sums of durations,
not an average of per-request rates. The archive enumerates all $5^5=3,125$
ordered paired-block resamples, takes each median log ratio, and exponentiates
nearest ranks 79 and 3047 for descriptive 2.5/97.5 percentile endpoints.
Requests are not resampled as independent replicates. Cross-block independence
is not established under shared page/NFS caches. At $n=5$ these ranges
are not coverage-guaranteed 95\% confidence intervals, significance tests or
power guarantees; shared-client/cache conditions further limit generalization.

\paragraph{Waiting and client outcomes.}
All five blocks show lower measured-QA median host demand wait and lower
client E2E with lookahead (Figure~\ref{f:paired-read-wait}). Wait reductions
range from 0.398 to 0.703 s per arm-median request; E2E reductions range from
0.384 to 0.827 s. Each request wait is the sum of anchored
\texttt{demand\_wait\_ns} invocation deltas, followed by a within-arm median.
Equal logical work and zero wasted bytes make this a measured scheduling
contrast rather than a smaller-workload comparison. The association is
consistent with less waiting, but is not a causal critical-path decomposition:
host waits cannot be added to client latency, and neither proves GPU overlap.

\paragraph{Overlap remains a separate gate.}
Both timing arms compile NVTX source annotations but run with
\texttt{FERRULE\_PROFILE\_NVTX=0}. No profiled timing is pooled here. A
separate first capture stopped in blocking before QA on an additional
profiler-library allowlist requirement: zero target ranges, lookahead
unissued, four official warnings and full-trace acceptance false. A collector
correction and independent capture remain outside this result. Physical
kernel/read/copy overlap requires accepted correlated activities and clock
alignment, not host-span intersections or the last read-ticket receipt.

\subsection{RQ4: Observed closure and the fault-contract boundary}
\label{sec:rq4}
All ten serving owners are recorded known closed with retained residency;
final logical read charges are zero. Authenticated \texttt{ECHILD}, absent
recorded descendants, stable-idle observations and released/reprobed locks
close process supervision. They do not prove post-drop physical release or
universal GPU quiescence. In particular, a host worker join cannot discharge
independent device custody, and retained residency is not a freed allocation.

Component fixtures cover exact source/ticket validation, alias-held quota,
deferred speculative errors, cancellation and drain. They are not integrated
fault injection in this HTTP study. E5 remains pending for delayed/stale
completion, cancellation at each stage, primary-plus-cleanup failure, owner
loss and lost ACKs. It must check publication/reuse and credit conservation
before and after named completion evidence, retaining Unknown capacity rather
than forcing zero. Algorithm~\ref{alg:terminal-custody} is the intended
contract, not a measured proof of fault recovery, eventual reclamation or
availability on every path.
