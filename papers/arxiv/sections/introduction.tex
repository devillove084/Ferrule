\section{Introduction}
\label{sec:introduction}

Storage-backed weight residency lets an inference owner repeatedly
materialize selected weights into a bounded execution cache. The problem is
to bound those copies and reuse their capacity safely, whether or not the
complete compact checkpoint could fit in host memory. Exceeding device
memory, exceeding aggregate physical residency, and choosing a controlled
cache budget are different conditions. Checkpoint file size, expanded weight
size and the request working set are not interchangeable: the latter also
includes activations, model state, staging, outstanding transfers,
allocator/driver reserves, metadata and resident file-backed pages.

\system{} follows \emph{plan, admit, materialize, publish, execute, retire}.
A source-bound plan fixes what is read; admission bounds covered claims;
completion validates the requested generation; custody prevents reuse while
physical references remain. Its concrete next-expert pipeline separates the
read window from owner compute submission. A safe blocking control waits on
the same worker immediately; lookahead submits one next selected read after
current upload and before current compute submission. The whole forward
remains synchronous. The question is whether this bounded scheduling change
reduces waiting while preserving quality, logical work and resource limits,
not whether a worker thread alone establishes hardware overlap.

\paragraph{Research questions.}
\begin{description}
  \item[RQ1 -- bounded completion.] Can a quality-accepted request finish
  with repeated materialization under declared accounting limits, and what
  physical memory is actually observed? A configured-budget point is not a
  capacity frontier or evidence that compact weights exceed physical memory.
  \item[RQ2 -- request I/O.] What demand is visible at the logical-reader
  and NFS-client levels after separating startup and request windows, and
  which attribution and backing-store quantities remain unknown?
  \item[RQ3 -- safe scheduling.] Under identical representation, quality,
  safety and budgets, how do blocking and bounded lookahead differ in host
  demand wait, speculative work and client outcomes? Correlated device overlap
  is a separate measurement question.
  \item[RQ4 -- custody and failure.] What closure is observed, and which
  fault cases still need to test stale publication, premature reuse and
  retained Unknown capacity?
\end{description}

\paragraph{Contributions and results.}
The paper contributes a resource model separating physical pools from
accounting domains; a source-bound materialization contract with exact
completion and custody; and structured normal, terminal and bounded-lookahead
algorithms with explicit integration limits. Its evaluation connects these
contracts to a completed, source-pinned serving experiment rather than to
implementation intent alone.

On the current serving source cut, nine exact-once factory gates pass for
constructor/provider and both schedules' full40, retained-fresh, ordinary
and cold-owner paths. A separate preregistered HTTP study then completes
five paired blocks, ten fresh lifecycles and all 120 requests, including
50 measured QA requests. It joins 900 actual worker token IDs to HTTP
terminal evidence, keeping eight-token oracle checks and two-token smoke
checks distinct. Every lifecycle records the same logical work, zero wasted
read bytes and a logical host high-water below its 64 MiB limit. With the
paired block as the analysis unit, lookahead has 8.18\% lower client E2E,
11.24\% lower TTFT and 10.91\% higher qualified serial-window goodput.
All five blocks show lower host demand waiting. These descriptive results
support bounded residency with measured wait reduction at this point, not
statistical coverage, general server throughput or a causal overlap claim.

The evidence has deliberate boundaries. Device samples are not certified
physical peaks; shared NFS counters are not NAS backend traffic; process
drain and known owner-local closure are not post-drop physical release.
Integrated fault injection remains pending. Earlier qualification cuts,
two stopped studies and four historical DEBUG plots are retained separately,
not borrowed as successful repetitions. The resident vLLM supplement has
unmatched arithmetic and total budgets and is not a SOTA comparison.
Storage inference and prefetch are prior art; no first-system, physical-memory
necessity, universal registry, multimodal or nonblocking-forward claim is made.
