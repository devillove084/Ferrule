# Generation -03: scoped overlap contract and direct-target preflight

This is a new, separately bound profile plan. `artifacts-go-20261015-01` stays
rejected and `artifacts-go-20261015-02` stays blocked. Neither is resumable or
eligible for scoped overlap. No ordinary paired data or production binary is
changed, and no old capture is reinterpreted as an inference measurement.

## Measurement change, declared before any launch

The pinned official Nsight Systems 2025.3.1.90 CLI supports
`--sample=none --cpuctxsw=process-tree`. Its CPU-only `status --environment`
check reports process-tree profiling and `perf_event_open` available on this
host. The proposed flags therefore change CPU context switches only: CPU
sampling, GPU metrics and GPU context switches remain disabled. CUDA, NVTX,
OSRT, file-access pread tracing and full non-lazy SQLite export remain required.
An absent-scheduling warning under **requested process-tree collection** is
unexpected and rejects this new scope; there is no automatic fallback/retry.

The local official User Guide distinguishes low-level userspace OSRT API
intervals from thread states inferred using scheduling data (sections
`command-line-options` and `os-runtime-libraries-trace`). The claim is only:

- Union of model worker `pread`/`pread64` wall intervals, intersected with union
  of actual expert math-kernel intervals.
- Separately, the allocation-plus-read `read_subset` envelope intersection.
- Neither interval proves active IO, physical NAS service, CPU execution or
  thread scheduling. Both can include CPU preemption; pread may hit page cache.

`scope_contract.py` declares exact warning dispositions; `analyze.py` retains
all raw diagnostics and global rejection. Only an exact official global
absent-scheduling message under an explicitly predeclared **none** policy can
be outside the wall-interval claim. Only exact no-payload warnings on a
separately authenticated non-CUDA wrapper role can be outside the model claim.
Such classifications **never** yield full-trace acceptance. A model warning,
unknown warning, loss in any process/severity, ambiguous role, orphan launch or
kernel, graph ambiguity, generation mismatch or incomplete expected read
coverage rejects scoped evidence too. A PID list is not authenticated role
proof. The new plan does not launch the historical traced wrapper as fallback.

SQL eligibility is not `scoped_overlap_accepted`. Final scoped acceptance also
requires the one frozen eight-token HTTP/oracle join, model PID/birth/source,
both raw map validations, dynamic owner-pair closure, authenticated ECHILD,
original all-eight stable idle and completed collector/export. The new plan
requires the maintained V2 idle window for eventual final physical observations.
No row-total comparison can substitute for these independent gates.
Dropped-event count stays unknown/null; simultaneous unreported API/activity
loss is not excluded. A final last read receipt is a positive source/operation
check, not an invented complete per-operation layer/expert journal.

## Direct-target custody blocker

The proposed command is `nsys profile ... /frozen/staged/cli serve ...`, with the
authenticated Python worker outside the trace. It is recorded as a **proposed**
command, not as a command that ran. The existing process topology instead is
worker -> nsys -> traced Python controller -> CLI. Only that controller has an
unreaped direct CLI child and can use the maintained direct-child termination
safely. Replacing it changes the custody contract, not just argv formatting.

On the current Linux 4.19 host, a CPU-only `pidfd_open(self)` syscall returns
`ENOSYS`; Python also has no pidfd wrapper. Checking `/proc/PID/stat` birth ticks
and executable SHA does not close the exit/reap/PID-reuse race for a child
owned and reaped by Nsight. The documented `nsys shutdown --kill` signals the
application **process group**, and `nsys stop` stops collection rather than
performing authenticated exact-child model shutdown. The frozen server exposes
no shutdown HTTP endpoint. No numeric-PID kill, group signal, ptrace scheme,
new general harness, production change or wrapper-substitute capture is added.

Consequently the measurement methodology is corrected, but the direct-target
lifecycle is not verified. Generation -03 is blocked **before** GPU locks,
GPU queries, model launch or either QA. Parent GO is recorded conditionally and
unconsumed. Fixing this requires a safe target-owned shutdown mechanism or an
explicitly revised custody/topology decision, not another blind capture.
